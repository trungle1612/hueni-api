# #17 — Authentication + admin layout

**Date:** 2026-10-01
**Issue:** #17 (epic #24, Step 3)
**Status:** Approved in brainstorming — awaiting written-spec review

## 1. Goal

Owners and the admin can log in with email + password, stay logged in on their phone, and log out. Logged-in users see the admin frame (navigation, user menu, empty dashboard) that later issues fill with real pages.

**Done when:** login and logout work; a system test logs in through the browser.

### Out of scope

| Item | Where |
|---|---|
| Password reset, any outgoing email, SMTP provider | #23 |
| Zalo login / self-registration | later issue (after deploy) |
| `place_memberships`, `accessible_place_ids`, 404 scoping | #18 |
| Dashboard content (homestay cards, free rooms, sync errors) | #20 |
| Timeline, feed management, user admin pages | #21, #22, #23 |

Until #23, accounts are created in the Rails console:

```ruby
User.create!(email_address: "lan@example.com", name: "Chị Lan", password: "…", role: "owner")
```

### Changes to earlier decisions

- **Styling:** the admin UI does **not** follow hueni's "Imperial Huế" design. It uses **Tailwind CSS + daisyUI 5, theme `autumn`** (chosen from mockups). Issue #17 and CLAUDE.md are updated accordingly.
- Password reset moves from #17 to #23.

## 2. Data

Generated by `bin/rails generate authentication`, then extended.

**`users`**

| Column | Rule |
|---|---|
| `email_address` | NOT NULL, unique; normalized (strip + downcase) by the generator |
| `password_digest` | `has_secure_password` (bcrypt); validation: minimum 8 characters |
| `name` | NOT NULL, validated present; shown in the UI |
| `role` | NOT NULL, default `owner`; DB check `role IN ('admin', 'owner')` + `enum :role, { admin: "admin", owner: "owner" }, validate: true` |

**`sessions`** (generator): `user_id`, `ip_address`, `user_agent`. One row per login; the cookie holds a signed, permanent session id, so owners stay logged in. Deleting a row logs that device out.

**Removed from generator output:** `PasswordsController`, `PasswordsMailer`, their views and routes (return in #23).

**Zalo later:** Zalo accounts will live in a separate `user_identities (user_id, provider, uid)` table; the only change to `users` will be a migration making `email_address` nullable. Nothing in this design blocks it.

**Places link:** many-to-many through `place_memberships` (several accounts per place, several places per account), built in #18.

## 3. Routes and controllers

| Route | Action |
|---|---|
| `GET /session/new` | Login page |
| `POST /session` | Success → redirect to the originally requested page or `/admin`; failure → redirect back to `/session/new` with alert "Email hoặc mật khẩu không đúng" (generator behavior) |
| `DELETE /session` | Log out → login page |
| `GET /admin` | `Admin::DashboardController#show` |
| `GET /` | Redirect to `/admin` |

- The generator's `Authentication` concern is included in `ApplicationController`: **every controller requires login by default**. Only `SessionsController#new/#create` opt out (`allow_unauthenticated_access`).
- `/v1/*` stays public (inherits `ActionController::API`, not `ApplicationController`). `/up` stays public (`Rails::HealthController`).
- Login is rate-limited by the generator (`rate_limit to: 10, within: 3.minutes`); message "Thử lại sau ít phút".
- `Admin::BaseController < ApplicationController` is created empty; every admin controller inherits it. #18 adds scoping there.
- User-facing strings are Vietnamese, written directly in views/controllers (single language, no locale file). Model validation messages come from `rails-i18n` (`vi`).

## 4. Styling setup

- `bundle add tailwindcss-rails` → `bin/rails tailwindcss:install` (creates `app/assets/tailwind/application.css`, adds the CSS watcher to `Procfile.dev` / `bin/dev`).
- daisyUI without Node: download `daisyui.mjs` (pinned daisyUI 5 release) into `app/assets/tailwind/`.
- `app/assets/tailwind/application.css`:
  ```css
  @import "tailwindcss";
  @plugin "./daisyui.mjs" { themes: autumn --default; }
  ```
  Only the `autumn` theme is compiled. No dark mode.
- Remove the empty `app/assets/stylesheets/application.css`.
- `assets:precompile` runs the Tailwind build, so the Dockerfile needs no change.
- System fonts (daisyUI default); no web fonts.
- Icons: a few inline Lucide SVGs (MIT) in `app/views/shared/_icon.html.erb`; no icon library.

## 5. Layout

`app/views/layouts/application.html.erb`: `<html lang="vi" data-theme="autumn">`, title "hueni admin".

**Not logged in** (login page): no navigation; centered content.

**Logged in:**

| Viewport | Frame |
|---|---|
| Phone (`< lg`) | Top `navbar`: "hueni" left, avatar (initial of `name`) right → dropdown with name, role label, "Đăng xuất". Bottom `dock` with the menu items; main content padded so the dock never covers it. |
| Desktop (`≥ lg`) | Fixed left sidebar: "hueni", `menu` with the items, footer with name, role label, "Đăng xuất". No dock. |

Flash messages render as daisyUI `alert`s at the top of the content area. Content container is mobile-first with a max width.

**Menu items** — one list in a helper (`admin_menu_items`), rendered by both dock and sidebar:

| Label | Icon | Path | Visible to |
|---|---|---|---|
| Tổng quan | home | `/admin` | everyone |
| Lịch phòng | calendar | — (#21) | everyone |
| Kênh OTA | refresh | — (#22) | everyone |
| Người dùng | users | — (#23) | admin only |

An item without a path renders disabled (dimmed, not a link) with a "Sắp có" badge in the sidebar. The current page's item is highlighted.

**Role labels:** `admin` → "Quản trị viên", `owner` → "Chủ homestay".

## 6. Pages

**Login (`sessions/new`):** centered "hueni" wordmark + subtitle "Quản lý phòng cho chủ homestay"; `card` with title "Đăng nhập", email and password inputs, full-width `btn-primary` "Đăng nhập"; error shown as `alert alert-error`.

**Tổng quan (`admin/dashboard/show`):** page title "Tổng quan"; dashed empty-state card "Chưa có homestay nào — Quản trị viên sẽ gán homestay cho tài khoản của bạn." (#20 replaces it).

## 7. Testing

- **`User` model:** name required; email required, unique, normalized; password < 8 rejected; role defaults to `owner`; unknown role rejected by validation and by the DB check.
- **Request tests:**
  - unauthenticated `GET /admin` → redirect to `/session/new`
  - correct credentials → `/admin`; wrong → redirect to `/session/new` with the alert, no session created
  - `DELETE /session` destroys the session row and redirects to login
  - `/v1/vacancy` and `/up` reachable without login
  - "Người dùng" menu item rendered for admin, absent for owner
- **System test (headless Chrome):** visit `/admin` → redirected to login → fill email + password → lands on "Tổng quan" showing the user's name → log out → back on login.
- **Fixtures:** `test/fixtures/users.yml` with one admin and one owner; passwords via `BCrypt::Password.create`, never stored in plain text.
